### Key Diagnostic & Architectural Findings:
1. **ktx Silent LLM 404 Route Failure:**
   - In `@kaelio/ktx@0.16.0`, `config.backend: gateway` uses `@ai-sdk/gateway` (`createGateway`), which dispatches to `POST <baseURL>/language-model`.
   - When pointing to `https://api.mistral.ai/v1`, Mistral's server returns **HTTP 404** (`{"message": "no Route matched with those values", "request_id": "8d6b3423a0afd83b7babe572ee679231"}`).
   - ktx's internal exception handler (`dist/context/scan/description-generation.js:617-638`) caught the 404 and degraded all descriptions to `null` to avoid an unhandled crash.
   - The all-null descriptions were written to `.ktx/db.sqlite` (`local_content_results`). Subsequent runs hit the resume cache and skipped re-querying (`recovered 9/9 descriptions, enriching 0`).
   - Token count was previously estimated at ~18.5k; verified truth is **0 tokens reached Mistral**.
2. **Postgres `reader` Role REFERENCES Grant (FK Fix):**
   - Originally, `reader` had only `SELECT` privileges. In PostgreSQL, `information_schema` views restrict foreign key visibility when the user lacks `REFERENCES` privileges.
   - As `postgres`, executed: `GRANT REFERENCES ON ALL TABLES IN SCHEMA public TO reader;` across both `olist` and `appdb`.
   - Verified that `reader` now discovers all 3 declared foreign keys via standard `information_schema.referential_constraints`, while write operations (`DELETE`) remain strictly refused (`permission denied`).
   - Rebuilt `appdb_v2` for Wren Engine (now compiles all 3 declared FKs into `relationships.yml` and `target/mdl.json`), ktx, and Datus.
3. **Wren AI vs. Wren Engine:**
   - We tested `wren-engine 0.6.0` (open-source core Python engine & MDL compiler), **not** the multi-container Docker Wren AI agent product.
